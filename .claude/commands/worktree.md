---
description: Create or enter a git worktree/branch with an exact name, e.g. /worktree chore/cleanup
argument-hint: <branch-name>
allowed-tools: EnterWorktree, ExitWorktree, Bash(git branch:*), Bash(git worktree:*), Bash(git rev-parse:*), Bash(git status:*), Bash(git fetch:*), Bash(git merge:*)
---

Get the session working in a worktree/branch named exactly `$ARGUMENTS` (it may contain a slash,
e.g. `chore/cleanup` or `feature/foo`, don't strip or alter it), creating it if it doesn't exist yet
or switching into it if it does. This lets one command serve both "start new cleanup work" and
"resume/hand off to work already in progress" without the caller needing to know which case applies.
Either way, the branch ends up caught up to the latest commit on main.

Steps:
1. If `$ARGUMENTS` is empty, ask the user what branch name to use and stop.
2. Run `git fetch origin main` so `origin/main` reflects the actual latest commit on main, not
   whatever it was last fetched to.
3. Run `git worktree list` and check whether any entry's branch is exactly `$ARGUMENTS`.
   - If one exists, call EnterWorktree with `path` set to that worktree's path. Switching into an
     existing worktree this way is allowed even if the session is already inside a different
     worktree, no need to exit first.
   - Once entered, run `git merge origin/main` to bring the branch up to date. If it merges cleanly
     (including "Already up to date"), continue to step 6. If it conflicts, stop, leave the merge
     for the user to resolve, and report which files conflict, don't try to resolve it yourself.
4. No existing worktree matches, so a new one needs to be created. If the session is already inside
   a worktree (from an earlier EnterWorktree call), creating a second one will be refused. Ask the
   user whether to exit the current worktree first (keep or remove it), don't assume either way.
5. Call EnterWorktree with `name` set to `$ARGUMENTS`. The project's `worktree.baseRef` setting is
   pinned to `fresh` (see `.claude/settings.json`), so it always branches from `origin/main`, never
   from whatever branch the session currently has checked out; combined with the fetch in step 2,
   that means the tip of main as of right now. It creates the worktree under `.claude/worktrees/`
   and switches the session into it, but it sanitizes the name (slashes become `+`, the branch gets
   a `worktree-` prefix), so the branch it creates will not yet be `$ARGUMENTS`. Immediately run
   `git branch --show-current` to capture that auto-generated name, then rename it to the exact
   requested name: `git branch -m <auto-generated-name> $ARGUMENTS`.
6. Confirm `git branch --show-current` now reports `$ARGUMENTS`, then tell the user the worktree
   path, the branch name, whether it was newly created or already existed, and (for the existing
   case) whether the merge from main was a no-op, fast-forward, or brought in new commits.

Don't touch any other worktree or branch, and don't push anything.
